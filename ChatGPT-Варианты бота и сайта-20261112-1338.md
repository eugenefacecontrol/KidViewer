**TL;DR\:** Да, **GitHub Pages + backend на твоём ноутбуке + SQLite** - вполне рабочая архитектура. Причём можно сделать практически бесплатно, с минимальным потреблением оперативной памяти и диска.

Я бы вообще не использовал Docker, PostgreSQL, Redis или другие тяжёлые компоненты. Для приложения, которым пользуются два человека, они избыточны.

**GitHub Pages**

## 2\. Насколько это будет лёгким?

Я бы выбрал **Python + FastAPI + SQLite**, поскольку здесь важнее простота поддержки, чем производительность.

Если хочется ещё легче, можно использовать **Go + SQLite**\. Получится один исполняемый файл без Python-окружения, но разработка может быть немного сложнее.

## 3\. Что важно предусмотреть

**GitHub Pages** действительно подходит для статического фронтенда, включая PWA. \[[Getting started with GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages?utm_source=chatgpt.com); [Get started developing a PWA - Microsoft Edge Developer documentation](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/?utm_source=chatgpt.com)\] Но он не сможет обращаться к `localhost` твоего ноутбука через интернет.

Для этого нужен доступный HTTPS API. Здесь подойдёт Cloudflare Tunnel: он работает через исходящее соединение, без проброса портов. \[[Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/?ref=arabroot.io&utm_source=chatgpt.com); [Tunnel fundamentals](https://developers.cloudflare.com/tunnel/concepts/?utm_source=chatgpt.com)\]

Есть несколько нюансов\:

- **CORS\:** разрешить запросы только с твоего GitHub Pages домена.
- **Авторизация\:** два пользователя с разными правами. Дайн не должен иметь возможности подтверждать собственные задания или редактировать их.
- **Фото\:** сжимать перед сохранением, ограничить размер загрузки, хранить в закрытой папке, а не в публичном GitHub.
- **Резервные копии\:** периодически копировать `tasks.db` и папку фотографий.
- **Доступность\:** ноутбук должен быть включён и не переходить в сон. При отключении ноутбука API недоступен.

Сам туннель не заменяет авторизацию - API нужно защищать отдельно.

## 4\. Можно даже обойтись без GitHub Pages

Есть ещё одна архитектура, которая мне нравится за простоту: **один FastAPI-сервер одновременно отдаёт фронтенд, API и фотографии**\.

Тогда не нужно настраивать CORS, а Cloudflare Tunnel предоставляет один HTTPS-адрес всему приложению.

Недостаток: когда ноутбук выключен, не открывается даже интерфейс. С GitHub Pages интерфейс останется доступен, а при необходимости можно добавить кеширование заданий.

## 5\. Мой выбор для первой версии

Я бы оставил GitHub Pages, FastAPI, SQLite и Cloudflare Tunnel, без Docker и без облачной базы данных.

В первой версии достаточно создания заданий, повторения по расписанию, загрузки фото, проверки выполнения и истории. Всё остальное можно добавлять постепенно.

**Но есть один момент, который я хочу уточнить\:** Дайн будет открывать приложение только дома, через тот же Wi-Fi, что и ноутбук, или ему нужен доступ из школы, с улицы и вообще из любой сети?

Это определяет, нужен ли нам Cloudflare Tunnel вообще. Если доступ только дома, архитектура станет ещё проще и легче.
