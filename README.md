# KidViewer

MVP Telegram-бота для спокойной структуры дня, где подросток сам показывает прогресс, а взрослый не живет в режиме бесконечных напоминаний.

## Что бот умеет

- утром показывает короткий список обязательных дел;
- дает подростку самому отмечать выполнение;
- сохраняет настроение дня;
- принимает сигнал "сегодня было слишком тяжело";
- отмечает задачу выполненной только после обязательного фото-пруфа;
- отправляет взрослым сводку и сигналы, когда день закрыт или когда было тяжело;
- различает роли по белому списку родительских `chat_id`;
- всем остальным чатам дает только детский функционал;
- позволяет админу задавать список задач на сегодня прямо из Telegram.
- дает родителю изолированный тестовый детский режим без изменения реальных данных;
- показывает частые команды в меню Telegram и на постоянной клавиатуре.

## Почему такой формат

Идея бота не в тотальном контроле. Он нужен, чтобы:

- убрать цикл "напомнили, не сделал, снова напомнили";
- перенести инициативу на подростка;
- оставить взрослому роль человека, который смотрит итог, а не охотится за нарушениями;
- фиксировать трудные дни без автоматического обвинения в лени.

## Запуск

1. Создай бота через `@BotFather` и получи `BOT_TOKEN`.
2. В корне проекта выполни:

```bash
cp .env.example .env
npm install
```

3. Открой `.env` и заполни:
   - `BOT_TOKEN=...`
   - `PARENT_CHAT_IDS=246529522,246529521`
4. Запусти бота:

```bash
npm run start
```

5. Напиши боту в Telegram:
   - из родительского чата отправь `/start`, потом `/summary`
   - из любого другого чата отправь `/start`, потом `/today`
6. Любой чат, которого нет в `PARENT_CHAT_IDS`, автоматически считается детским.

## Быстрый запуск

Если коротко, то последовательность такая:

```bash
cp .env.example .env
npm install
npm run start
```

Потом вставляешь токен в `.env` и пишешь боту в Telegram.

## Как узнать chat_id

Если нужно проверить `chat_id`, можно:

1. временно запустить бота;
2. написать ему `/start` из нужного чата;
3. добавить логирование `ctx.chat.id` или использовать уже известные родительские ID.

В твоем случае родительские ID уже заданы:

```text
246529522,246529521
```

## Настройка

В `.env` можно менять:

- `TASKS_JSON` — базовые дела на день;
- `TIMEZONE` — часовой пояс;
- `MORNING_CRON` — утренний пинг;
- `EVENING_CRON` — вечерняя сводка;
- `PARENT_CHAT_IDS` — список родительских `chat_id` через запятую.

Пример:

```json
["Почистить зубы", "первые 25 минут математики", "вторые 25 минут математики", "Третьи 25 минут", "Четвертые", "Покормить животных"]
```

## Команды

- `/start` — справка по роли текущего чата
- `/today` — детский экран задач на сегодня
- `/summary` — родительская сводка по всем детским профилям
- `/children` — список детских профилей и их `chat_id`
- `/settoday` — задать ребенку задачи на сегодня
- `/testchild` — открыть изолированный детский экран для проверки кнопок, настроения и фото

Пример `settoday`:

```text
/settoday 123456789
Почистить зубы
первые 25 минут математики
вторые 25 минут математики
Третьи 25 минут
Четвертые
Покормить животных
```

В детском режиме нажатие на незавершенную задачу выбирает ее для подтверждения. Задача
становится выполненной только после следующей фотографии. Нажатие на уже выполненную задачу
снимает отметку и удаляет привязанный к ней пруф из состояния бота.

Все чаты из `PARENT_CHAT_IDS` получают уведомления, когда ребенок:

- выбирает задачу и должен прислать фото;
- подтверждает задачу фотографией;
- снимает выполнение задачи;
- выбирает любое настроение;
- отмечает, что сегодня было слишком тяжело;
- закрывает все обязательные задачи дня.

Повторное нажатие без изменения состояния и действия внутри `/testchild` уведомления не
отправляют.

В родительском чате команда `/testchild` каждый раз начинает новую тестовую сессию. Тестовые
отметки хранятся только в памяти процесса, не попадают в `data/state.json`, родительскую
сводку и автоматические уведомления.

## Обновление VM без Git

С локального Mac отправь исходники на VM через `rsync`. Локальные `.env`, данные, зависимости
и история Git не копируются и не перезаписывают соответствующие файлы на VM:

```bash
cd /Users/yauhenisheima/Sources/KidViewer
rsync -av \
  --exclude node_modules/ \
  --exclude .git/ \
  --exclude .env \
  --exclude data/ \
  ./ opc@89.168.85.86:/home/opc/Sources/KidViewer-main/
```

После копирования установи точные зависимости и проверь сборку:

```bash
ssh opc@89.168.85.86 \
  'cd /home/opc/Sources/KidViewer-main && npm ci && npm run check'
```

Затем запусти бот в фоне. `nohup` не даст процессу завершиться после закрытия SSH,
а вывод будет записываться в `bot.log`:

```bash
cd /home/opc/Sources/KidViewer-main
nohup npm run start > bot.log 2>&1 < /dev/null &
echo $! > bot.pid
```

Проверить процесс и последние строки лога:

```bash
ps -p "$(cat bot.pid)" -o pid,etime,cmd
tail -n 100 bot.log
```

Наблюдать за логом в реальном времени:

```bash
tail -f bot.log
```

Остановить фоновый процесс перед следующим обновлением:

```bash
kill "$(cat bot.pid)"
rm -f bot.pid
```

## Хранение

Состояние хранится локально в `data/state.json`. Для MVP этого достаточно.

Telegram здесь используется как интерфейс управления и журнал действий для родителей. Как единственный полноценный сторэдж он неудобен, потому что Bot API не дает боту нормально читать произвольную историю чата назад.

## Что можно добавить следующим шагом

- отдельную кнопку "запросить компьютер";
- разные уровни задач: база, дом, учеба;
- недельные отчеты по настроению и выполнению;
- SQLite/Postgres вместо локального JSON;
- подписи/имена детей вместо `chat_id` в родительских сводках.
